# Listful Thinking 0.2.0-rc.3 — public self-hosting candidate

RC3 packages the V18 list and website-capture workflows with a public HTTPS Docker profile. It is a release candidate for independent small self-hosted instances, not a multi-tenant hosted service.

## Changes since RC2

- 14-day recoverable Trash and 56-day public guest-link expiry.
- Account setup and recovery links, password changes, inactive-owner list handoff, and private-by-default collaboration controls.
- Reviewed website capture for products, recipes, events, and how-to pages. Wishlist entries retain variants, seller, availability, source, and the time a price was checked.
- Guest reservation correction and release, grocery shop controls, mobile workspace improvements, and current README screenshots.
- First-admin setup code; production startup checks for HTTPS, secure cookies, CSRF, rate limiting, and safe scraper settings.
- Public `compose.public.yml` with Caddy, a mounted setup secret, constrained app runtime, live SQLite backup and verified upgrade helpers.
- AGPL-3.0-only license and a visible source-code link. The tag build points users at this exact source tag.
- Strict dependency and container scans before CI publishes an amd64/arm64 image with SBOM, provenance, and a signature.

## Install or upgrade

Use the [public self-hosting runbook](../deployment/public-self-hosting.md) and its [full Compose example](../deployment/self-hosting-handbook.md#public-https-example-with-caddy). The image name is `ghcr.io/utrost/listful-thinking:v0.2.0-rc.3` **only after the tag's publish workflow succeeds**. The GHCR package must be public for anonymous pulls; otherwise sign in to GHCR.

Back up the existing SQLite database before upgrading. RC3 includes forward-only Flyway migrations through V18. Test a restore and retain the matching pre-upgrade snapshot before attempting any rollback to an older image. The public profile does not expose the app port directly; point DNS at the host and allow Caddy to obtain a certificate on ports 80 and 443. Generate the setup secret before the first start.

## Limits

This is a single-instance SQLite deployment. It has no high-availability or multi-tenant isolation. Website extraction is best-effort and saves a reviewed snapshot, not synchronized prices. Self-hosters must schedule off-host encrypted backups, monitor updates, and verify their own domain, TLS, email, and restore path. See the [current risk register](../current-state-and-risk-register.md).
