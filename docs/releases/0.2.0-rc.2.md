# Listful Thinking 0.2.0-rc.2 — privacy and security review

This candidate supersedes RC1 for testing and deployment. It retains the planning, recovery, templates and workspace features, with fixes from the [personal-data security review](../security-review-2026-09-26.md).

- Application administrators see usage counts instead of private list titles, descriptions and dates.
- Remote images require a deliberate click; uploaded images remain local.
- Stored share-token hashes cannot be used as public links.
- Deactivation permanently revokes existing sessions and email links, even after reactivation.
- Cross-origin writes are rejected, recovery tokens leave the address bar immediately, logout clears private drafts, and responses carry no-store/noindex headers.
- Scraper checks reject private IPv6 translation/tunnel destinations; SMTP verifies TLS hostnames; SQLite files use private permissions.
- Updated Java dependencies and CI scanning of resolved runtime versions replace the incomplete POM-only check. The final 77-component inventory has zero OSV advisory matches at review time.

## Upgrade

Back up first. Migration V16 adds session/token revisions without removing existing list content. Rollback to RC1 requires the previous image and its matching V15 database snapshot. The `/admin/lists` API now returns per-user counts only. Password creation/reset enforces BCrypt's 72-byte UTF-8 limit.

The release provides a Linux amd64 Docker archive (`listful-thinking:v0.2.0-rc.2`), a Java 17 JAR, the resolved runtime SBOM, and SHA256SUMS. Build tagged source for other architectures. Follow the [self-hosting handbook](../deployment/self-hosting-handbook.md) for persistent storage and environment settings.

## Data privacy boundary

List content is **not end-to-end encrypted**. The server and backups remain trusted. Public links last until revoked and can be forwarded. Trash and old backups retain deleted content. For personal information prefer authenticated invitations, encrypted disks/backups and a private network or HTTPS deployment.
