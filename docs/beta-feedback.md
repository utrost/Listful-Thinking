# Independent self-hoster feedback

We are looking for people outside the project to try the public RC3 image on their own Docker host. The [local trial](../README.md#try-the-prebuilt-image-locally) takes one machine; the [HTTPS guide](deployment/public-self-hosting.md) is for a public domain. Use sample or non-sensitive data for this evaluation and keep your own backup.

Try three journeys without coaching:

1. Set up the first admin, create a wishlist, and capture one public product page. Correct one suggested field before saving.
2. Capture a recipe, event, or how-to page into another list type. If extraction fails, try the manual draft.
3. Share a list, try the guest view in a private window, make a backup, and find the restore instructions.

Send feedback using the [issue forms](../SUPPORT.md). If a screenshot or URL contains personal information, describe the problem with fictional details or ask for a private contact channel without posting the data. Useful details: installation time, browser and device, app version/digest, page URL if public, the first step that felt unclear, what you expected, what happened, and whether you could recover without help. Report a vulnerability through [SECURITY.md](../SECURITY.md).

The maintainer should track how many people completed setup, capture, sharing, and a backup/restore drill; record median setup time and the top three blockers. Do not treat maintainer-run Playwright checks as independent usability feedback.
